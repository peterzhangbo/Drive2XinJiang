# 大北疆带狗自驾攻略 V8 修复设计

## 1. 目标

在保留“单个 HTML、可离线打开、无需构建工具”交付方式的前提下，修复 V7 已发现的事实、交互、数据一致性、安全和可访问性问题，并把全程充电规划升级为可执行的冗余方案。

完成后的页面应让使用者能回答四个问题：

1. 当前执行的是哪条正式政策。
2. 每段路先去哪里充电，拥堵或故障时去哪里替代。
3. 什么时候必须切换备选、绕行或折返。
4. 页面里的里程、住宿夜数和预算是否能自动保持一致。

## 2. 约束与非目标

- 保留现有单文件 HTML 作为最终交付物。
- 保留现有视觉语言、十个栏目、离线 SVG 场景、确认中心和本地保存能力。
- 不引入 React、Vue、打包器、后端或在线数据库。
- 不把静态网页包装成充电桩实时监控工具；实时占用、故障和价格仍以车机及运营商 App 为准。
- 不承诺未经运营商或主管部门证实的桩数、功率、宠物政策或营业状态。
- 不扩大原有18天路线，除非触发充电绕行或道路关闭预案。

## 3. 已确认的根因

### 3.1 事实不同步

同一事实被复制到总览、注意事项、逐日数据和核验记录中。更新时只改了部分副本，造成“独库仍是征求意见稿”和“充电已经全覆盖”等冲突。

### 3.2 交互状态没有统一恢复

地图跳转只负责展开目标日，没有清除逐日筛选状态，因此目标卡片可能仍处于隐藏状态。

### 3.3 汇总数字是手写值

预算总计、里程和夜数没有从分项计算，修改分项后不会自动更新汇总。

### 3.4 充电规划只有单点说明

现有表格多以“某服务区/某城市快充”表达，没有统一记录备选站、切换阈值、绕行代价和最后安全决策点，无法应对排队、故障或临时关闭。

## 4. 方案选择

采用“单文件交付＋结构化数据＋独立校验脚本”。

- 页面中的行程、充电和预算仍由原生 JavaScript 渲染。
- 对容易变化或容易重复的数据建立单一数据源。
- 增加一个零依赖 Node.js 校验脚本，检查静态事实和汇总结果。
- 最终用户仍只需打开 `大北疆带狗自驾攻略.html`。

## 5. 页面数据设计

### 5.1 充电路段数据

每个关键路段使用统一结构：

```text
路段ID
适用日程
出发地与目的地
主站
备选A
备选B
实时核验渠道
切换阈值
最后安全决策点
绕行或折返方案
证据等级与核验日期
```

每个站点至少记录：

- 可搜索的站名或服务区名。
- 城市/道路位置。
- 运营商或“第三方公共桩”。
- 已证实的功率口径；无法证实则写“以 App 为准”。
- 导航或官方入口。
- 该站承担的角色：主站、同城备选、沿线备选或应急补能。

### 5.2 充电切换规则

默认规则：

- 预计排队超过20分钟，切换同城备选。
- App显示不可用桩超过一半，或无法确认站点开放，直接使用备选。
- 预计到站电量低于20%，不再追求原主站，选择更近的可用站。
- 无人区、山路或弱信号区进入前，必须保有到达下一安全城镇或下下个已确认站点的电量。
- 主站与备选都不可确认时，不进入风险路段，执行绕行、延迟出发或折返。
- 进入 G7 临白段、阿禾、赛湖环湖和独库前，在“最后安全决策点”完成第二次核查。

### 5.3 充电覆盖范围

下列路段都要有主站＋备选A＋备选B；无法提供三个独立站点的路段，第三层必须是明确的绕行或折返方案：

- 北京—临河。
- G7 临河—额济纳。
- 额济纳—哈密。
- 哈密—乌鲁木齐。
- 乌鲁木齐—江布拉克—可可托海。
- 富蕴—布尔津—阿勒泰—阿禾往返。
- 布尔津—乌尔禾。
- 乌尔禾—赛里木湖。
- 赛里木湖—伊宁—那拉提。
- 那拉提—独库北段—奎屯。
- 乌鲁木齐—哈密及返程 G7/G30。

### 5.4 预算数据

预算分项保留上下限，页面合计由 JavaScript 自动相加。两晚条件营地失败后的酒店费用不得重复计入；如需要额外安全余量，应列为独立分项而不是藏在合计中。

### 5.5 政策与动态事实

关键事实展示统一包含：

- 当前结论。
- 证据等级。
- 官方或运营平台来源。
- 来源发布日期。
- 页面最后复核日期。
- 下一次必须人工复核的时间。

独库北段更新为正式生效口径，删除“等待最终通告”表述，并补充预约时段、入口、处罚和12123咨询信息。

## 6. 用户流程

### 6.1 查看充电方案

用户进入“充电补能”，先看到全程统一规则，再按日程查看每个路段的主站、两个备选及切换条件。风险路段突出显示最后安全决策点和绕行方案。

### 6.2 出发前确认

确认中心为每个关键充电路段生成任务：

- 出发前24小时确认主站和两个备选。
- 抵达上一安全城市或最后安全决策点时再次确认。
- 记录最终采用的站点、异常原因和绕行决定。

### 6.3 地图跳转

点击地图节点时：

1. 切换到逐日行程。
2. 自动将筛选恢复为“全部18天”。
3. 展开目标日。
4. 滚动到目标卡片。

### 6.4 页面刷新与离线使用

确认中心和清单继续用 `localStorage` 保存。保存失败必须显示提示；清单保存也使用与确认中心一致的异常处理，不能让脚本中断。

## 7. 可访问性与安全

- 导航采用 `tablist`、`tab`、`tabpanel` 语义。
- 当前栏目同步更新 `aria-selected` 和键盘焦点顺序。
- 所有可点击地图节点继续支持 Enter 和空格。
- 补充清晰的 `:focus-visible` 样式。
- 为减少动态效果的用户关闭淡入、平滑滚动和非必要动画。
- 所有新窗口链接统一添加 `rel="noopener"`。
- 移动端导航保留横向滚动，同时增加右侧渐隐或文字提示，让用户知道还有栏目。

## 8. 校验与测试设计

### 8.1 零依赖静态校验

新增脚本验证：

- 18个逐日对象且日期、日序唯一。
- 逐日里程合计与展示值一致或在明确的四舍五入范围内。
- 17个住宿夜晚由15晚酒店＋2晚条件营地组成。
- 预算上下限等于分项求和。
- 每个关键充电路段都有主站、备选A、备选B或明确绕行。
- 关键动态事实带来源和复核日期。
- 不再出现已知过期文案：独库征求意见稿、当前已实现全覆盖、赛湖固定24个快充等。
- HTML中不存在重复ID。
- `target="_blank"` 均带 `rel="noopener"`。
- 本地文件链接存在。

### 8.2 TDD顺序

1. 先让校验脚本对当前 V7 失败，证明能抓到预算、旧政策、链接和充电备选缺失。
2. 修复数据与文案，使静态校验通过。
3. 为地图筛选跳转建立浏览器复现，确认修复前失败、修复后目标日可见。
4. 验证确认中心及清单保存异常不会中断页面。

### 8.3 浏览器验收

- 页面身份、首屏内容、控制台健康。
- 十个栏目均可切换。
- 行程筛选、展开、地图跳转、确认中心、清单保存正常。
- 桌面和375×844移动视口无页面级横向溢出。
- 充电表在移动端可阅读，主备切换规则不被截断。
- 打印预览保留18天逐日卡片，不输出交互控件。

## 9. 验收标准

- 所有 P1、P2、P3 审计问题均有对应修复。
- 页面不再包含互相冲突的充电或独库政策表述。
- 全程关键补能路段全部具备三层冗余或明确绕行。
- 静态校验脚本全绿。
- 地图筛选回归场景通过。
- 浏览器控制台无相关错误或警告。
- 桌面和移动端截图能够证明主流程可用。
